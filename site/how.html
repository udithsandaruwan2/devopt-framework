How it works

Gates before code.
Packs before files.

The agent is a facilitator, not an autopilot. It drafts the next document, asks at most three questions, and waits. You approve the gate. That is how you avoid paying for the wrong build.

The path

0 IntakeBrief. Gate G0.
1 DiscoveryProblem evidence. G1.
2 ProductPRD + catalog. G2.
3 ArchitectureADRs + stack. G3.
4 PlanTasks and slices. G4.
5 BuildSmall diffs. G5 per task.
6 ReleaseVersion + rollback. G6.
7 OperateLearn, then loop.

The one-shot prompt covers Phase 0 and Phase 1 in one sitting, then stops. Later phases are the same pattern: one artifact, one gate.

Context packs

The agent runs ./scripts/context-pack.sh kickoff (or implement-web / implement-api) and opens only that list. Frontend and backend profiles never load together.

Human production

Promotion tracks keep dev/* and prod/* apart. promote.sh is dry-run until you say go. Agents do not merge to production.

Token budget

AGENTS.md stays under 140 lines. Session baseline is 2,234 tokens, capped at 3,500. Skills load only when their trigger matches.
